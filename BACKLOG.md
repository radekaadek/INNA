# Backlog: experiments that could improve the ball tracker

Baseline to beat (SN-Tracking-2023 test, `ball_r18` candidates, hit = within 2% of frame width): greedy 77.6% recall / 71.4% precision;
Viterbi offline 81.5 / 78.8, causal 78.9 / 76.7; ball-in-crop 88.9 (greedy) / 90.5 (offline) / 89.0 (causal).
Rules: tune only on the 6 validation clips; run the test set once per final configuration; single seed, so treat differences under ~2 points as noise.
Where failures come from (error analysis, `notes_viterbi.md`): 9.6% wrong pick with the ball in the top-10, 6.0% ball not a candidate, 3.0% no estimate;
68% of failed frames are in runs >= 8 samples (track locked on a wrong object).

### Research notes + new ideas #19-#22 (2026-11-07, from a pasted 2026 survey of MOT / SOT)
Survey: tracking-by-detection MOT (YOLOv12 / RT-DETR / Ultralytics detectors + ByteTrack, BoT-SORT, (Deep)OC-SORT, HybridSORT via BoxMOT) and single-object tracking (SUTrack, EdgeDAM).
Findings (web search, mostly secondary sources, indicative only): these trackers are Kalman + IoU/appearance association built for pedestrians; a racquetball study (via a literature review) reports ByteTrack ADE 114 px vs DeepOCSORT 31 px, i.e. a linear motion model fails on abrupt ball motion, and detector misses cascade. ByteTrack's low-score second association stage is the one idea that fits tiny balls. No direct ball-in-broadcast evaluation was found. For 5-8 px balls box IoU is meaningless, so use centre distance. Our Viterbi tracker is already a global single-object version of this. YOLOv12 beats RT-DETR-R18 on COCO speed/accuracy; RT-DETR had better small-object recall in aerial imagery and DETR was more stable than YOLO11x on a small ball in one sports paper; nothing for broadcast soccer. SUTrack (AAAI 2025, chenxin-dlut/SUTrack, MIT weights on HF xche32/SUTrack) is a ViT template/search tracker for LaSOT-style objects, not tiny balls. EdgeDAM: no accessible code found.
